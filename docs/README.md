# File to JS — Documentation

`file-to-js` turns any file into **JavaScript source**: a `var` holding the
file's bytes as an array of numbers, so the content can ship inside a
script instead of being loaded from disk or from the network at run time.
It is both:

- **a command line tool**, `file-to-js`, run from a build script to embed
  binary or text files (images, fonts, archives, data) in a `.js` file;
- **a C++ library**, namespace `XYO::FileToJS`, with the conversion as a
  function (`fileToJS`), and the tool itself as a class that can be
  embedded in another program.

One output form:

```js
var data=[
	0x89,0x50,0x4E,0x47,...
];
```

```
applications, build scripts ...

xyo-system            (Shell, IApplication, ShellArguments)
xyo-encoding, xyo-multithreading, xyo-data-structures,
xyo-managed-memory, xyo-platform
```

It is the JavaScript sibling of `file-to-cs` (C/C++ source) and
`file-to-rc` (Windows resources), with the same command line conventions.

## Why it exists

A script that needs a binary resource can fetch or read it, but then the
file must be deployed next to the script, found at run time and kept in
step with it. Embedding it in the source makes the script
self-contained. Doing that by hand means encoding every byte; `file-to-js`
does it as a build step:

| Problem | What `file-to-js` does |
|---------|------------------------|
| A file must ship inside a script | writes it as `var name=[0xHH,...];` to load or concatenate |
| Binary content can not go in a string literal safely | every byte is written as `0xHH`, nothing is interpreted |
| Regenerating on every build changes the output every time | `--touch=file` regenerates only when the input is newer than the output, then touches `file` |
| Several resources in one generated file | `--append` adds a `var` to an existing output |
| Long build command lines | `@file` response files |

## Concepts at a glance

| Need | Command line | Library |
|------|--------------|---------|
| Embed a file | `file-to-js --name=logo --file-in=logo.png --file-out=logo.js` | `XYO::FileToJS::fileToJS("logo", in, out, false)` |
| Several `var`s in one file | second and later calls with `--append` | `append = true` |
| Regenerate only when changed | `--touch=file` | `Shell::compareLastWriteTime` yourself |
| Use it as bytes in JS | | `new Uint8Array(logo)` |
| Use it as text in JS | | `new TextDecoder().decode(new Uint8Array(text))` |
| Run the tool from your own program | | `XYO::FileToJS::Application::Application` (`file-to-js.application.static`) |
